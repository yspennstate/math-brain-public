# What changed on 2026-09-03

The math brain, mostly. The general-brain hooks got one trigger rewrite. Everything below was
measured before it landed; the instruments ship with the change.

## The vendored math brain is now the lineage the hooks actually run

`mathbrain/` had been carrying an older lineage of the package (the v4 evaluation tree). It could not
open a store written by the current one: `EdgeKind('semantic_association')` is unknown to its models,
so the vendored `dreaming/math_sense.py` hook - which imports the package beside it - failed at the
first edge and, being fail-safe silent by design, said nothing. A broken hook and a quiet hook look the
same; that is exactly the failure its health check was written for.

`mathbrain/` now carries the current lineage: the population tooling (integrator, harvesters, the
evidence-class layer, the assumptions-visible renderer) merged with the query-window renderer, the
index-signal cache and the injection hook's health check. 126 files in, 124 of the old lineage out;
the additive `association/` layer and the vendored-layout `conftest.py` are kept. The package's own
suite runs green in this layout (527 passed, 5 skipped for platform reasons).

The tools that used to hard-code one machine's directories now resolve from the environment:
`MATHBRAIN_BUILD` (the package root by default), `MATHBRAIN_INBOX` (`<build>/inbox` by default) and
`MATHBRAIN_STORE` (the population store; required by the hook, as before). Nothing in `mathbrain/`
names a filesystem path any more.

`retrieval.py` gains one measured knob, `MATHBRAIN_QUERY_TF` (`linear`, the default; `log`; `binary`).
The lexical channel had always saturated and length-normalised the document side but weighted a
query term by its raw count, so a long argument that repeats a common word fifteen times paid any node
that says it once fifteen times over. The default is unchanged until the arms are graded on the held-out
probe tier; the knob is there so that grading can happen on the same code.

## A probe-bank evaluator that scores through the hook's own path

`dreaming/eval_math_probes.py` scores the tiered probe bank (470 tier-1 probes the ranking constants
were tuned on, 263 tier-2 held out, 318 whose theorem is absent from the store; the three files are
under `dreaming/state/`) by running `retrieve()` and then the hook's own `_select()` with the live
gates, so a number it prints is what a connected agent would have been served. It reports a hit two
ways - by the labelled node id and by normalised, accent-folded title - because the store holds several
copies of most theorems and the labels predate the copies. Runs need `MATHBRAIN_STORE`.

What it measured on the store it was built against (4,732 nodes): tier-1 block hit 55% by id and 64% by
title, tier-2 29%, and a block served on 98% of the unanswerable probes. The last number is the one to
sit with: the abstention gates in `math_sense.py` (`MIN_SUPPORT`, `MIN_MARGIN`) sit two orders of
magnitude below the scores the ranker produces, and no single score feature separates a correct block
from a wrong one on a topic the store covers - a lexical floor keeps about half the correct blocks while
cutting nine tenths of the false ones, and the score margin runs the wrong way, because duplicate copies
make correct answers close-scored. Left as measured; the gate is not moved by a threshold sweep alone.

## The vendored math hook is the current one

`dreaming/math_sense.py` had been the 22 August version, 426 lines behind the hook that actually runs
(and it imported the package that could not open the store). It is now the current hook with the same
deployment-neutral path block: the statement-for-lede swap, the margin test against a distinct-title
rival, the conditional campaign demotion, the hint under every note, evidence nodes kept out of the
served block, and a claim's recorded read shown beside its hint. Smoke-tested through the vendored
package against a real store.

## A hand read of a claim goes on the record

`mathbrain/tools/record_review.py` writes an agent's read of a claim into the store's evidence table as
a discovery report - linked to the claim, never an authority, no status change; the store's own
promotion rules say a theorem is verified only by a Lean kernel check with formalisation fidelity, or a
human proof review with an independent reproduction. A human's read goes in as `HUMAN_PROOF_REVIEW`
under a human-reviewer key the tool refuses to mint. `tests/test_record_review.py` covers the round
trip, idempotence, a recorded gap and the missing-key refusal. The hook shows the latest read beside
its hint: "an agent read on 2026-09-03 by <who>: no gap found; unverified".

## The fire logs rotate without losing a row

`dreaming/rotate_logs.py` can now be applied. Every session's hook appends to the fire logs at any
moment, so a read-then-replace loses whatever lands in between; the writers already serialise on a
per-file lock (`append_journal`), so the rotation plans outside the lock, appends the moved rows to
monthly archives outside the lock, and holds the lock only to write the kept rows plus the delta
appended meanwhile and to count the result. The self-test drives a writer through the real lock during
a rotation of 60,000 rows (none lost, no fragments) and a negative control restores the pre-rotation
copy on a failed count. The live window is 21 days, a week clear of the longest reader's lookback.
`instinct_prime.py` now writes the suppressed-fire log through the same lock.

## Two triggers rewritten to their referents

`money_number_states_its_estimand` fired on "last 24h" in a metrics query, on "the test made 144
assertions" and on prose that merely discussed ways to make money. Rewritten so that the window phrase must sit
beside a P&L word, a made/lost count must be money, and "what … make" no longer matches. Replayed on
five days of real tool inputs: keeps 6 of its 125 past fires, adds none on 25,967 other inputs; the two
positive controls match and the three negative ones stay silent, run through the hook itself.

`steelman_opposite` (a guide, "write the strongest case that you are wrong") matched "therefore",
"clearly" and "proven" inside proofs, LaTeX and code comments - 528 fires in three days, four of eleven
judged on-domain. Rewritten to the verdict sentence ("the answer is", "I conclude", "this shows that",
"the verdict is", "QED", ...): keeps 3 of 146 joined fires and adds 14, and the additions are proofs
closing with QED and a "the verdict is PASS", which is the referent. Both landed in the durable homes
the compiler reads (the learned overlay for the first, the seed table for the second) after a recompile
by another session had erased a hand edit of the compiled table; the compiled artifacts are rebuilt
from those homes. The private reflex table is not part of this repository; the changes are recorded
here because the replay bench and the method are.
