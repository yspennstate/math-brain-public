# What changed on 2026-10-15

Six weeks of work on the deployment this framework comes from, brought back in one pass. Three themes:
compaction stops losing things, recall got measured and the measurements decided the defaults, and the
hooks got cheaper to run and harder to ignore. Everything below was measured before it landed, and the
instruments ship with it.

## Compaction becomes part of the brain

A context compaction used to be the moment a session forgot. Now each one is kept.

`compact_nodes.py` runs on Claude Code's `PreCompact` and `PostCompact` events (both settings templates
wire it directly, since the dispatcher handles neither event). Before the compaction it tells the
summarizer what to keep: open asks with their task ids, commit and landing ids, the next step. After it,
it saves the summary as a brain node under `~/.claude/brain_graph/compactions/` and links it to the
session's previous compaction, to a compaction hub, and to the memories and files the summary names.
`compact_nodes.py --sweep --days 1` rebuilds missed nodes from the transcripts, so a session that
compacted while the hook was down can still be recovered. `codex_manual_compact.py` gives Codex sessions
the same record: Codex compacts natively, and the tool saves an agent-written summary with a provisional
anchor. `compact_math.py` stages a math-only digest for review. Its files end in `.json.pending`, so nothing
ingests them before that review.

`compact_hooks.py` and its 53 texts in `compact_hooks.jsonl` push sessions to compact at task boundaries
rather than at the window's edge. A hook fires on a measured signal: a checklist entry closed, a final
report, a push, a token count past 200k, 250k or 280k, a large tool result, a long idle gap on a big
context. At most one fires per event, each has a per-session cooldown, and within a kind the one shown
least recently goes first. Two texts check the result after a compaction. One confirms the node was saved.
The other says when it was not and names the sweep command. The node is written by the `PostCompact` hook,
which runs beside `SessionStart` and often finishes 5 to 20 seconds later, so a check made at
`SessionStart` reported a missing node on every fire we logged. When the node is not there yet, the check
now waits for the session's next event and looks again; it reports a missing node only after 180 seconds
with nothing written.

`compact_on_task_end.py` goes one step further on Windows. Claude Code accepts `/compact` only as typed
input, and no hook output can trigger it. So when a turn closes a task on a large context, this Stop hook
starts a windowless helper. The helper waits until the session is idle and then types `/compact` into
that session's own console. It acts only for interactive sessions, and only when the turn closed a task
on a large context. The file `COMPACT_ON_TASK_END_OFF` in the dreaming folder turns it off, and on other
platforms it does nothing.

## Recall: what the measurements kept

A study ran across the main brain and the math store, with held-out questions and token counts on every
arm. The defaults follow its results.

- **Whole cards beat snippets.** `math_recall.py` prints whole cards with their ids and links. On the same
  100 questions, whole cards with ids scored 83 and title-and-snippet output scored 34.
- **Several wordings in one call.** `--or` takes two or three phrasings of the question in a single call:
  86 of 100, against 76 with one wording per call. Phrase them the way a card would, by the object, the
  method's name or the author.
- **Walk instead of searching again.** `math_recall.py --id <id>` reads a card whole along with its links.
  `math_walk.py` prints a compact map of the cards around one and suggests which way to step. Walking
  reached the same answers as searching again (82 against 83) on about half the uncached tokens.
- **A weak match is flagged.** A `WEAK MATCH` line tells the agent to reword rather than read on. When the
  line appeared, the answer card was among the printed cards for 4 of 21 questions; when it did not, for
  49 of 79.
- **Spreading is off by default.** `diffusion.py` (personalised PageRank over the use-grown graph) and
  `--depth` remain available. On this bank they only re-ordered cards the words had already found: 79
  against 80 without them, at 46 percent more tokens. Learned co-use edges (`math_strength.py`) did not
  move the score either. They ship for inspection, not as a default.
- **The math lexical channel.** In the math package, recall uses BM25 with b = 0.4 and counts titles twice,
  plus the meaning channel. On a held-out bank of 584 questions that went from 298 to 317 correct (27
  gained, 8 lost, p = 0.002). The main brain's `bm25.py` keeps k1 = 1.2, b = 0.75.
- **Meaning vectors for new memories.** The embedding sidecar is rebuilt every few hours. Before this
  change, a memory written in between was scored on its words alone. `fresh_vectors.py` writes a small
  overlay for those memories with the same encoder, and refuses to write if the encoder does not
  reproduce three sidecar rows to cosine 0.9999. `query_embed_proc.py` encodes the query in its own
  process: building the ONNX session holds the GIL for about 0.65 s, and that used to freeze recall's main
  thread. With the meaning lane on, hit@1 went from 35 to 39 of 56 and MRR from .529 to .551.
- **A prepared cache.** `fastrecall.py` keeps the half of a search that does not depend on the question in
  a marshal file, keyed by store state, code and environment. A cold call went from 5-6 s to about 1.5 s.
  `math_recall_prebuild.py` keeps that file current as the store changes.
- **Exact names.** When a prompt or command names a file that a scar card is about, `exact_name.py`
  pushes that one card, once per session. A name that too many cards mention pushes nothing.
- **Prior work on open problems.** `problem_recall.py` returns everything already tried on a problem, by
  id or by statement, in one call.
- **Facts that moved.** `moved_facts.py` reads a deployment's own `moved_facts.json`, a list of things that
  changed on a known date. It flags an older memory that still describes the old state. No registry
  ships with the framework, and without one the module stays silent.

## Hooks: cheaper, and fair to each other

- **A fair share of the context budget.** Claude Code passes a model at most about 10,000 characters of
  one hook command's output, and spills the rest to a file the model never reads. The dispatcher now
  divides its budget fairly among the hooks that fire, weights the work-fitting hooks three to one, and
  names the overflow file in its first line when it had to cut. `enabled_if` lets an entry run only when a
  flag file exists.
- **No repeats.** `hook_seen.py` answers one question: has this receiver already been given this exact
  block since its last compaction? Exact repeats had been 15 percent of all hook-context characters.
- **In-process by default.** `hook_dispatch_extend.py` adds a hook to the dispatcher's in-process list once
  its output has been proven identical to a standalone run. It never removes a name. One group of 28
  hooks, each of which had been starting its own Python process, went from 2.29 s to 0.12 s per tool call.
- **Slow reflexes found.** `instinct_cost.py` times every reflex trigger on a 16 KB tool call. One
  learned trigger, with two unanchored DOTALL lookaheads, had been costing 5 to 8 s per large edit for two
  weeks. Triggers are now checked for cost when they are built. Safety scars fire first, and a superseded
  memory is caught when its reflex fires rather than after.
- **A clock that cannot run ahead.** `clock_stamp_hook.py` reads the text a tool call is about to write
  and objects when a time stamp's earliest possible meaning is already in the future. Plans ("until",
  "by") are left alone.
- **Messages reach their recipient.** `live_inbox_hook.py` shows a session the mesh messages waiting for
  it, within one tool call. Before this, a message sat unread until the agent ran `inbox` itself.
- **Starting an agent means saving its work.** `agent_launch_save_hook.py` fires when an agent, task or
  workflow is launched, and when a shell command starts a headless worker. It asks where that worker's
  output will survive if the worker is cut off.

## The task checklist and the prompt layers

The checklist hook registers each request a session receives, together with the requester's words and the
time. Agents mark entries `working`, `done`, `blocked`. The `seen` mark belongs to the person who asked,
never to the agent. `work_timer.py` tracks a timed request against its deadline.

`owner_prompts_hook.py` serves recent requests in layers: what has been said more than once, then
everything on the threads this session touches, then the last two days elsewhere. Each part stays under
the harness's per-hook limit. A re-ask and a loop's echo are now counted separately, so a prompt a loop
re-fired 118 times no longer reads as one asked 118 times. `owner_prompts_brains.py` splits the same
material by brain (main, math, movie). Each brain gets one budgeted part per context and then only the
new important prompts.

## Smaller

- `bootstrap/install.py` renders `templates/CLAUDE.template.md` into the new home, so a fresh install's
  agents get the recall method, the task checklist and the compaction note from their first session.
  `--partner` names the person they work with. An existing `CLAUDE.md` is never overwritten; the
  rendered text goes to `CLAUDE.brain.md` beside it.
- `foresight.py` dates its forecasts, so a stale one reads as stale.
- `hook_liveness.py` notices a hook that stopped firing.
- `brain_node_documents.py` and `remember_index` keep a memory recallable within seconds of being
  written.
- `eval_paraphrase_reach.py` checks that a stored result is still found when the question names it in
  other words.
- Every new script returns early on `-h` and `--help`, which `test_help_flag_is_inert.py` enforces.
- Two script-style tests skip under pytest collection instead of running there.
