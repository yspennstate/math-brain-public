# What changed on 2026-11-15

A month of work since `CHANGES_2026-10-15.md`. Four themes: recall got cheaper where a measurement said it could,
several checks were found to pass on empty input and were fixed, agents now queue for shared launchers instead of
racing for them, and the open-problem work gained GPU samplers that other problems can reuse. Each item names the
measurement behind it and the file it lives in.

## Recall

The association walk in `framework/dreaming/graph_lane.py` now takes 8 steps instead of 16. On 22 seed questions the
whole printed answer was identical at 8, 10 and 16 steps, the same agreement two runs at 16 steps have with each
other. On 40 bank questions seeded by words alone, 8 steps took 0.13 s against 0.25 s, shared a median of 20 of its
top 20 results with a 100-step walk (19 at worst), and put the correct card at the same rank as 16 steps on all 40.
The saving is about 0.1 s of a 1.5 s served call. The step count is part of the walk cache's name, so a cached
16-step result is never served as an 8-step one.

Pruning the same walk with the Andersen, Chung and Lang push (FOCS 2006) was tried on the deployed graph of about
390,000 nodes and lost to the 8-step walk at every tolerance.

The word walk used by the writing tools now moves between senses rather than words. The old neighbour list joined
every sense of a word, so a walk could enter a word in one meaning and leave in another (berth, then office, then
curacy). The lexicon builder writes one link list per sense, drawn from WordNet's synsets and its synset and sense
relations (Miller, 1995; Fellbaum, 1998), and the walk leaves a word only through the sense it entered by. The links
are symmetric, so the Metropolis-Hastings walk still targets the same stationary law.

## Checks that passed on nothing

Four checks were found reporting success because their input was empty or their tool could not run. Each is fixed
and each left a rule.

- A secret scan piped one tool's output into a counter. The first tool was missing from the machine, exited 127, and
  the counter read zero bytes and printed zero hits. A scan now prints the bytes it read and refuses on a non-zero
  exit upstream.
- An absence check tested that a leaked value was "not in" a set of files, with a reference that had come back
  empty. Every "not in" was true. The check now asserts the reference before testing absence.
- A push verification used `grep -P`, which in a non-UTF-8 locale exits 2 without matching. The loop read exit 2 as
  "no match" and reported a correct push as missing. Verification now compares `git rev-parse origin/main:<path>` with
  `git hash-object <path>` and treats any exit above 1 as an error.
- A hook appended to a shared log with a plain append. On Windows that is a seek to the end followed by a write, so
  two hooks firing in the same instant wrote at the same offset and the shorter row covered the start of the longer.
  33 of 540 rows in one log were such tails. Shared logs now take a per-file lock for every append.

A fifth was a gap rather than a false pass: `push_paths.sh` falls back to the GitHub API when it loses a race for the
branch tip, and the API lanes never run git's pre-push hook, so the privacy scan that guards this repository was
skipped on that path. The fallback now runs the same scan before any API call.

## Agents sharing a launcher

A lock file that admits one Codex start per ten minutes is not a queue: waiters polled once a minute, the first to
poll after the interval won, and one run lost every round for ninety minutes, gave up and exited 0. The harness in
`framework/experiments/codex_probe/` now keeps a ticket per waiter (first-wait time, touched each minute, ignored after
three minutes untouched), lets only the oldest live ticket take the lock, and exits non-zero when it gives up. Its
driver judges a run by the `ANSWERS.md` it produced, not by its return code. The full report, and two others between
agents, are in `how_agents_work/agent_reports.md`.

## Credit

`results/CREDITS.md` lists the authors our public papers cite (88 papers, 79 with a reference list, 1,509
references) and the prior work each open-problem result names in its own README. It is rebuilt by
`framework/scripts/build_credits.py`, which reads the papers' `.bib` files or their `\bibitem` lists and the result
READMEs. It shows who is cited, not how much each contribution mattered. The hooks in `framework/citation_hooks/`
ask, while a paper is being written, for what existed before, what is new, and how the two are related, so that the
introduction and the AI declaration name the mathematicians whose work the paper rests on.

## GPU samplers for open problems

Two samplers written for single problems are general enough to reuse.

`results/open-problems/P0133_ust_torus_dual_theta_2026_11/ust_metal.swift` samples uniform spanning trees by Wilson's
algorithm (STOC 1996) on an Apple GPU, one tree per GPU thread, with no Xcode project and no Python GPU library: the
Metal kernel is a string compiled at run time. The walk, the sum pass and the lift pass run as one loop with a phase
variable, so a thread that finishes one phase starts the next without waiting for the others. It drew 48,000 trees of
40 by 40 in 0.4 s and a million trees of 160 by 160 in 206 s, and agreed with the CPU sampler within two standard
errors on every statistic compared. Memory is threads times vertices times 10 bytes (2.7 GB for 4,096 threads at 256
by 256), so size it against free memory first. The same structure fits any loop-erased-walk statistic.

`results/open-problems/P0108_thin_cylinder_fpp_clt_2026_11/` has a first-passage percolation solver (Bellman-Ford
iterated to its fixed point) in two ports, PyTorch for NVIDIA GPUs and MLX for Apple GPUs, with a `--check` mode that
compares a small case against an exact CPU Dijkstra. It is written for line-to-line passage times across periodic
cylinders and reads its lengths and widths from
environment variables, so other width schedules need no code change.

## The working record, added later the same day

Several folders now hold the intermediate work behind the results, not only the results. Each has a README that
says what is in it, how far each claim was checked, and whose work it builds on.

- `results/open-problems/codex-rounds-2026-11-14/`: five rounds of worker attempts on rows of the list, with each
  worker's brief, running log, proofs, scripts and final report, and the coordinator's vetting of every claimed result.
- `results/open-problems/proof-checks-2026-11-12/`: checks of solutions that others reported for problems on the
  list, made before a row is taken off it: reading notes, scripts recomputing finite cases, and what was taken on trust.
- `results/open-problems/frontier-worker-results-2026/`: the working folders of the October solvers. Each holds the
  routes tried and why each dead route died, the claims and their versions, one agent's audit of another's claim,
  and the receipts tying a claim to the hash of the file that was checked.
- `results/open-problems/frontier-worker-drafts-2026/`: drafts and measurements on three rows of the list. A draft is
  marked unaudited until an independent audit admits it.
- `results/open-problems/fei-papers-2026-11/` and `fei-step-constant-numerics-2026-09/`: the code, derivations and
  audits behind the posted FEI papers, and the step-constant certificates.
- `results/open-problems/problem-intake-2026-09-11/`: how problems were collected and ranked before work began.
- `framework/dreaming/`: about 250 of the scripts the brain runs, with a README grouping them (recall, hooks,
  compaction, proof receipts, judging the brain's own notes, consolidation, evaluations). The set is partial: the
  main entry point and the reflex engine stay private.
- `results/notes/`: twelve more notes of 15 November, among them the T264 risk tail exponent, the P0165 gap that
  turned out to be closed in the literature, and a fault in the GPU normal sampler's far tail on Apple hardware.

What this buys a reader: a claim can be traced from the paper back to the route that produced it, the audit that
admitted it, and the file that was checked. A failed route is recorded with its reason, so the next attempt does
not repeat it.
