# Staged named-theorem checker

This candidate fixes a claim boundary: a definition-only file, an unavailable source file after compilation, and `--file ... --target Absent` could all produce PASS in the pinned baseline. Three independent mocked baseline reproductions confirm those paths. None required launching Lean.

`lean_check.py` now reports useful compilation as `COMPILED_NO_NAMED_TARGET` or `COMPILED_SOURCE_UNREVIEWED`, exit 3. Exit 0 is reserved for `FORMAL_TARGET_VERIFIED`: a matching caller review assertion, exact source/generated/compiler hashes, a named theorem (not a definition or axiom), and exactly one transitive axiom receipt containing only `propext`, `Classical.choice`, and `Quot.sound`. `sorryAx` and custom axioms fail. Failed tactics never establish mathematical falsity. Translation fidelity always remains UNVERIFIED in this interface.

Review assertions are supplied by the caller through `--reviewed-sha256`. This is not proof that a human or independent reviewer read anything. The caller must actually inspect executable Lean source, imports, macros and metaprograms. Stdout can be forged by arbitrary source; exact marker matching rejects ordinary ambiguity but is not authentication. A dishonest review assertion can still produce a false certificate. The compiler and imported dependency bytes remain a trust assumption. The dependency manifest is pinned across execution, but every `.olean` is not independently validated.

Implementation uses the root campaign's separately developed, source-inspected `windowless_job_v2.py`, copied without changes as `lean_process.py`. It starts suspended with no window and BelowNormal priority, assigns a native Job Object before resuming, and owns cleanup by handles. This lane has not independently re-run its native process tests or <=50ms window observer. Core compiler integration is likewise UNVERIFIED until the root schedules it. The candidate directly invokes the pinned compiler with an existing dependency environment, avoiding `lake env` builds or toolchain downloads. Fresh compute admission occurs before launch and periodically during execution.

Compatibility: `--stmt`, `--file`, `--target`, `--full-mathlib`, and `--selftest` remain. `--core`, `--timeout`, `--json`, and `--reviewed-sha256` are added. The intentional exit-code change prevents old callers from treating uncertified compilation as proof; those callers need review. Default timeout is 120s, configurable up to 900s. Unicode/quoted Lean declaration names and `prelude` source files are outside this narrow candidate interface and fail closed. Anonymous `example` declarations can compile, but cannot receive a named-theorem certificate.

Integration requires installing three files together: `lean_check.py`, `proof_receipt.py`, `lean_process.py`. Root must independently inspect and test the candidate, validate exact source hashes, acquire live/canonical file claims, preserve the previous bytes, and deploy both runtime and canonical copies. No such deployment has occurred in this lane.
