1. A multiplicative soft-clique Gibbs weight strong enough to favor near-cliques has essentially all of its `L_2` Fourier mass at degree `Theta(k^2)` when `k=Theta(log n)`, so simple low-degree Fourier truncation of that deformation is the wrong route.
2. A singleton-block randomized greedy procedure constructs an exact clique of size

   `log_2 n - O(log log n)`

3. For a fixed clique prefix `C` of size `s`, a trial block `B`, and candidate `v in B`, the score

   `H_{B,v}^C = E_v^C [1-(N_B^C-1)^2]`

# 3. Mathematical idea before code

The useful category change is to separate **verification** from **search**.

For any fixed `k`-set `S`, let

`D_S(Y) = sum_{e in binom(S,2)} (1-Y_e)`

be its number of missing internal edges. Then

`q_S(Y) = 1 - D_S(Y)`

is a degree-one polynomial and satisfies

`q_S(Y)=1` if `S` is a clique,

`q_S(Y)<=0` otherwise.

So a fixed candidate clique has an exact unit-gap **linear threshold certificate**. There is no `Theta(k^2)` threshold-degree obstruction to *verifying* a proposed clique. The quadratic degree appears when one insists on the exact Boolean indicator `prod_e Y_e`, or when one tries to Booleanize an exponentially large family of candidate witnesses uniformly.

This observation changes the search target: the source problem is fundamentally an **adaptive witness-extraction / search-PTF** problem. A successful route has to exploit the signs and margins of many low-degree witness certificates without paying the degree required to turn each certificate into an exact `0/1` bit.

No code is useful for that conceptual step, so no checker-only artifact is produced this run.

# 4. B1 — CHANGE THE CATEGORY: from clique polynomials to adaptive search PTFs

## 4.1 Fixed-witness verification is threshold degree one

The identity above is worth making explicit because it rules out a tempting but incorrect diagnosis:

`"a log n clique contains Theta(log^2 n) required edges, therefore any exact search polynomial must have degree Theta(log^2 n)."`

That inference is false at the threshold level. For a fixed `S`, one linear polynomial already separates cliques from non-cliques with unit gap.

The real issue is existential extraction: among a very large collection of fixed witnesses `S`, select the vertices of one witness having `q_S>0`.

## 4.2 A fixed clique prefix already admits a low-degree first-extension PTF

Let `C` be a fixed clique prefix of size `s`, and order fresh candidate vertices as `v_1,...,v_M`. Define the exact eligibility monomial

`e_j^C(Y)=prod_{u in C} Y_{u v_j}`.

Although `e_j^C` has degree `s`, this is still only `O(log n)` at the target scale. More importantly, the event that `v_j` is the **first eligible candidate** has a unit-gap polynomial-threshold representation of the same degree:

`p_{C,j}(Y) = e_j^C(Y) - 2 sum_{ell<j} e_ell^C(Y)`.

Because every `e_ell^C` is exactly `0` or `1`,

- if `j` is the first eligible index, `p_{C,j}=1`;
- if `j` is ineligible and no earlier candidate is eligible, `p_{C,j}=0`;
- if some earlier candidate is eligible, then `p_{C,j}<=-1` whether or not `j` itself is eligible.

Hence

`p_{C,j}>0`

if and only if `v_j` is the first eligible extension of this **fixed** prefix `C`, and

`deg p_{C,j}=s`.

Thus even lexicographic symmetry breaking is cheap once the prefix is fixed.

## 4.3 The residual object is an adaptive search threshold program

The prefix, however, is not fixed globally. At stage `s`, the next family of eligibility monomials depends on the vertices selected at stages `1,...,s-1`. This is naturally viewed as a branching/search program:

- a node is a clique prefix `C`;
- outgoing tests are low-degree threshold certificates `p_{C,j}`;
- exactly one outgoing branch is taken under the deterministic priority rule when an eligible candidate exists;
- depth is `Theta(log n)` on the desired event;
- the final output is the set of vertices on the realized branch.

For an ordinary nonadaptive decision list whose tests are already Boolean variables, exponentially separated weights can compile “first satisfied rule” into a polynomial threshold representation; this is one reason the decision-list PTF literature is structurally relevant. But our tests are themselves prefix-indexed polynomial inequalities, and off-path tests are still algebraically present in a static polynomial. Existing decision-list results do not by themselves gate away those off-path branches.

### B1 outcome

The target is now narrower:

`compile an adaptive depth-O(log n) search tree of low-degree unit-gap threshold certificates into n output polynomials of degree O(log n), on G(n,1/2), without exact Booleanization of every off-path predicate.`

This is a better statement of the missing mechanism than “polynomialize greedy.”

# 5. B12 — FIND WHAT IS CONSERVED: the realized singleton trajectory Booleanizes automatically

The previous singleton-block construction used bulk block sizes

`M_s = ceil(2^s/L^2)`,

where `L=log_2 n`, together with

`R = ceil(2 A L^3)`

fresh trial blocks per bulk level for a fixed constant `A>0`. At a bulk level `s`, conditional on the actual clique prefix and all previous history, the number of eligible vertices in a fresh block is

`N ~ Bin(M_s, 2^{-s})`.

Write

`lambda_s=M_s 2^{-s}`.

For `s >= ceil(2 log_2 L)`,

`1/L^2 <= lambda_s <= 2/L^2`

for large `n`.

The previous report used only the probability `P(N=1)`. Here the important invariant is stronger: **along the actually executed trajectory, blocks with three or more eligible vertices disappear with high probability.**

### Proposition 5.1 — trajectory Booleanization

For the singleton-block greedy construction from the previous report, with probability `1-o(1)`, every bulk trial block actually examined along the realized trajectory has

`N in {0,1,2}`.

#### Proof

For a fixed fresh bulk block, condition on the actual prefix and the entire previous revealed history. The relevant edges from the fixed prefix into this block are still independent Bernoulli `1/2`, so the displayed binomial law is exact. Since

`1_{N>=3} <= binom(N,3)`,

we have

`P(N>=3 | history)
 <= E[binom(N,3) | history]
 = binom(M_s,3) 2^{-3s}
 <= lambda_s^3/6
 <= 4/(3 L^6)`.

The algorithm allocates at most `R` bulk trials at each of at most `L` bulk levels, so the number of examined bulk blocks on any realized trajectory is `O(L^4)`. The conditional estimate is uniform in the realized history. A union bound, followed by the tower property if desired, therefore gives

`P(any examined bulk block has N>=3) = O(L^4/L^6)=O(L^{-2})=o(1)`.

The initial regime uses singleton blocks, where trivially `N<=1`. This proves the proposition. QED.

### 5.2 Consequence for the local score

Recall

`U_B^C = 1-(N_B^C-1)^2`.

On the trajectory-Booleanization event,

- `N=0` gives `U=0`;
- `N=1` gives `U=1`;
- `N=2` gives `U=0`.

Thus **on every block the actual algorithm examines**, `U_B^C` is an exact Boolean bit with probability `1-o(1)` globally over the whole trajectory.

If the blocks at one fixed prefix are ordered `B_1,...,B_R`, define

`F_j^C = U_j^C - 2 sum_{ell<j} U_ell^C`.

On the same good event, `F_j^C=1` exactly for the first singleton block, `F_j^C=0` for failed blocks before it, and `F_j^C<=-1` after an earlier singleton occurs.

For a candidate `v in B_j`,

`G_{j,v}^C
 = E_v^C U_j^C - 2 sum_{ell<j} U_ell^C`

has degree at most `3s`, and on the good trajectory is positive exactly for the unique vertex in the first singleton block.

### 5.3 Why this does not yet solve the source

The proposition Booleanizes the **realized** trajectory, not all hypothetical prefixes simultaneously. A static output polynomial cannot simply ignore off-path prefixes unless an additional compiler mechanism gates them away. There are far too many hypothetical prefixes for the `O(L^{-2})` trajectory estimate to be union-bounded over the whole search tree.

That is now the key invariant/failure boundary:

- on-path local decisions are already Boolean and degree `O(log n)` with high probability;
- off-path algebraic contributions are the obstacle.

This is substantially sharper than blaming local equality tests or the greedy trajectory itself.

### B12 outcome

The remaining source difficulty is an **off-path suppression problem**. A successful polynomial need not improve the local extension test; it must prevent the exponentially many unrealized prefix certificates from corrupting the thresholded output.

# 6. B23 — DO WHAT THE PROPOSER DID NOT EXPECT: try to break the obvious certificate aggregators

I tested the main ways one might try to turn the path certificates into a global selector before investing in them.

## 6.1 Raw linear aggregation fails for a structural sign reason

For each fixed candidate path `P`, the previous report gives a low-degree signed certificate with

`Phi_P=1` on a valid path,

`Phi_P<=0` on an invalid path.

A raw weighted sum

`sum_P a_P Phi_P`

with positive coefficients does **not** behave like an OR of the valid-path events. Invalid paths do not contribute zero; they can contribute large negative values. Making the weights lexicographic does not cure this: an earlier invalid path with a large negative score can dominate a later valid path, while reversing the weight order simply moves the same problem to later invalid paths.

Thus the usual exponentially separated-weight trick for an ordinary decision list cannot be applied until false path predicates have been converted from “nonpositive” to something close to `0`.

This is a route diagnosis, not a lower bound on all possible polynomial aggregators.

## 6.2 Even square-root cancellation does not rescue uniform candidate-by-candidate approximation

Consider the older graph-independent architecture in which one preselects `M` candidate `k`-sets and separately approximates each exact clique indicator

`AND_m`, where `m=binom(k,2)`.

A fixed `k`-set is a clique with probability `2^{-m}`, so any graph-independent candidate family having constant success probability must have

`M >= c 2^m`

for some fixed `c>0` by the union bound.

Suppose one tries to avoid the previous worst-case `M epsilon` accumulation by assigning random signs or otherwise hoping for square-root cancellation of the individual uniform approximation errors. Even in that optimistic architecture, keeping the aggregate false signal `O(1)` with comparable coefficients requires an individual error on the scale

`epsilon <= M^{-1/2}`

(up to polynomial factors). Hence

`log(1/epsilon) = Omega(m)`.

The standard vanishing-error approximate-degree lower bound for `AND_m` is

`deg_epsilon(AND_m) = Omega(sqrt(m log(1/epsilon)))`.

Therefore this optimistic square-root-cancellation regime still forces

`deg = Omega(m) = Omega(k^2)`.

At `k=alpha log_2 n` for any fixed `alpha>0`, this is `Omega(log^2 n)`, not the required `O(log n)`.

This argument does **not** rule out graph-dependent/adaptive candidate generation, nonuniform typical-instance approximations, or a compiler that never approximates each candidate separately. It rules out one broader family of “enumerate many fixed candidates, approximate each one, then linearly aggregate” ideas, even after granting square-root rather than worst-case error accumulation.

## 6.3 Softmax/positive-part is exactly the missing nonlinear operation

The signed certificates would be easy to aggregate if one could replace each `Phi_P` by a bounded polynomial `R(Phi_P)` satisfying approximately

`R(1)=1`,

`R(x)≈0` for all attainable `x<=0`,

with sufficiently small aggregate error over the relevant path family, while keeping the **composed edge degree** `O(log n)`.

But this is precisely a polynomial approximation to the positive-part/step operation over a large family of off-path certificate values. The previous uniform-AND barrier and the present square-root-cancellation stress test both warn that demanding exponentially small error candidate-by-candidate is likely to return to quadratic degree.

The correct route, if one exists, must therefore exploit a structural correlation of the *adaptive search tree* so that most off-path certificates never need independent Booleanization.

### B23 outcome

Three tempting global compilers are now deprioritized:

1. raw positive weighted sums of signed path certificates;
2. graph-independent candidatewise approximation plus union-bound error control;
3. the same candidatewise architecture with only square-root aggregate error control.

The open lane is an adaptive/distributional compiler that suppresses unrealized prefixes collectively rather than Booleanizing them one by one.
