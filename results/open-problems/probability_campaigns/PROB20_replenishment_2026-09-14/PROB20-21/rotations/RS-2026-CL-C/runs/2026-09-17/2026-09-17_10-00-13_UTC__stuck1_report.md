# 4. (b) Routes tried and the precise failure of each

This inventory is cumulative across the RS-2026-CL-C reports. No route below is re-run here.

### Route 1 — literal polynomialization of sequential greedy

Restricting the early graph so that all earlier vertices are greedily selected turns the final exact selection bit into an AND of `n-1` edge variables. Therefore any polynomial *equal to the exact Boolean greedy selection bit* can have degree `n-1`.

**Failure:** exact Boolean reproduction of the literal greedy bits is the wrong object. The source only thresholds real polynomial outputs, and AND itself has a low-degree threshold separator. The restriction argument does not lower-bound source-valid thresholded real outputs.

### Route 2 — deterministic `S_n` averaging

Conjugating a successful polynomial by a vertex permutation preserves degree and distributional success. But deterministic Reynolds averaging can move selected coordinates from `>=1` down to the `1/2` boundary; the two-vertex exact witness already shows this.

**Failure:** symmetry is safe as a distribution over polynomials, not by coefficient averaging of the thresholded search output.

### Route 3 — exact enumeration of candidate cliques

The first-clique selector can be made exact with zero source-style rounding errors, and its degree was improved from `2 binom(k,2)` to exactly `binom(k,2)` by linear weighting of exact clique indicators.

**Failure:** `binom(k,2)=Theta(k^2)`. Under a degree `O(log n)` budget this reaches only `k=Theta(sqrt(log n))`, so it proves no positive `alpha_LD`.

### Route 4 — Fourier projection of an exact selector

A rigorous bridge was proved: if an exact clique selector has `o(1)` total Fourier mass above degree `D=O(log n)`, then scaling its low-degree projection yields a source-valid polynomial with high probability.

**Failure:** no selector with the required `o(1)` tail is known. The natural exact/discontinuous selectors appear too noise-sensitive, and the bridge by itself gives no tail bound.

### Route 5 — soften fixed clique indicators and truncate

A multiplicative Gibbs weight favoring a `k`-set with few missing edges has an exact binomial Fourier-level distribution. To tilt a typical `k`-set down to only `O(k)` missing edges, the deformation parameter forces most `L_2` mass to degree `Theta(k^2)`.

**Failure:** at `k=Theta(log n)`, simple low-degree truncation still pays `Theta(log^2 n)`.

### Route 6 — enumerate many fixed candidates and approximate each one

A graph-independent candidate family needs about `2^{binom(k,2)}` candidates even to have constant chance of containing a `k`-clique. Uniformly approximating each AND predicate tightly enough for either worst-case accumulation or even optimistic square-root accumulation forces `log(1/epsilon)=Omega(k^2)`, and the standard vanishing-error approximate-degree lower bound for AND then gives degree `Omega(k^2)`.

**Failure:** candidate-by-candidate uniform Booleanization cannot reach `k=Theta(log n)` at degree `O(log n)`. This is an architecture barrier, not a lower bound for the source problem.

### Route 7 — randomized singleton-block greedy

Fresh blocks were sized so that a block has exactly one common neighbor with useful probability. With sufficiently many blocks per level, a valid exact clique path of size

`log_2 n - O(log log n)`

exists along the realized run with probability `1-o(1)` while using only `o(n)` preallocated vertices.

**Failure:** this is an algorithmic existence/search process, not yet one static vector polynomial. The adaptive prefix is still hidden in the execution history.

### Route 8 — signed fixed-path certificates

For every fixed candidate path, adding rather than multiplying the local extension scores yields a degree-`O(log n)` certificate that equals `1` on a valid path and is nonpositive on an invalid path.

**Failure:** the source needs one vector output. A positive weighted sum does not act like OR because invalid certificates are not zero; a large negative false certificate can swamp a later valid one. Lexicographic weighting merely relocates the swamping problem.

### Route 9 — fixed-witness and fixed-prefix threshold certificates

A fixed clique has threshold degree one via `1 - (# missing edges)`. For a fixed prefix, the first eligible extension has a degree-equal-to-prefix-size unit-gap threshold representation.

**Failure:** the prefix itself is adaptive. Substituting/gating across successive prefix choices can multiply degrees or leave off-path tests algebraically active.

### Route 10 — on-trajectory Booleanization

For the singleton-block construction, with probability `1-o(1)` every block actually examined along the realized trajectory has only `0`, `1`, or `2` eligible vertices. The local quadratic score therefore becomes an exact Boolean bit on all examined blocks simultaneously.

**Failure:** that high-probability event is indexed by the actual path. A static polynomial sees exponentially many hypothetical prefixes. The good-trajectory probability cannot be union-bounded over the entire unrealized tree.

# 6. B20 — FIND WHY THE ALGORITHM FAILS: the failure is a masking/composition failure

The singleton-block algorithm has three conceptually separate layers:

1. **eligibility:** is candidate `v` adjacent to every vertex of the current prefix?;
2. **local choice:** which candidate/block is the first valid extension?;
3. **global routing:** which prefix is the actual prefix whose local choice should affect the final coordinates?

Layers 1 and 2 already have degree-`O(log n)` threshold descriptions at the desired depth. The failure is layer 3.

Any successful compiler has to achieve one of the following without multiplying the degree by the path depth:

- a one-sided low-degree mask which acts like `1` on the realized prefix and like `0` (not merely a large negative number) on almost all unrealized prefixes;
- a redesign in which only polynomially or subexponentially many prefixes can remain algebraically live, with their aggregate leakage provably below the `1/2` output margin;
- a global polynomial observable whose coordinates directly encode a coherent clique and never explicitly enumerate prefixes.

The current signed certificate `Phi_P in {1} union (-infinity,0]` is insufficient because linear aggregation respects sign but not Boolean OR. Applying a generic positive-part/step approximation to every `Phi_P` risks an additional polynomial degree factor, which would turn `O(log n)` into `O(log^2 n)`.

Thus the exact algorithmic failure can be summarized as

\[
\boxed{
\text{adaptive routing} + \text{one-sided masking}
\quad\text{without}\quad
\text{degree multiplication}.
}
\]

### B20 outcome

**The missing ingredient is not a better local clique predicate. It is a low-degree masking/composition principle for the adaptive prefix tree. No new claim is made.**

# 7. B22 — READ THE FAILURES, NOT THE SUCCESSES: nearest solved mechanisms and what they lack

## 7.1 Wein 2022: sparse independent set, local algorithm -> low-degree polynomial

Nearest source-family success: Alexander S. Wein, *Optimal Low-Degree Hardness of Maximum Independent Set*, Math. Stat. Learn. 4 (2022), arXiv:2010.06563. In sparse `G(n,d/n)`, low-degree polynomial algorithms achieve the same half-optimal scale as the relevant local algorithms. The paper’s positive direction approximates a local algorithm by a low-degree polynomial.

This is the closest direct proof that an algorithmic random-graph search procedure can be compiled into the low-degree model while preserving a nontrivial witness guarantee.

**What it has that CL-C currently lacks:** a genuinely local dependency structure. A vertex decision is determined by a bounded-radius sparse neighborhood, so one can truncate/encode the finite local view. The dense greedy clique trajectory is adaptive and its static dependency object contains exponentially many hypothetical prefixes even though the realized path has length only `O(log n)`.

This distinction is exactly reflected in Wein’s dense `G(n,1/2)` discussion: matching achievability at the greedy scale is left open, and the Randomstrasse 2026 problem is built around that surviving gap.

## 7.2 Podolskii--Proskurin 2022: decision lists as polynomial threshold functions

Vladimir Podolskii and Nikolay Proskurin, *Polynomial Threshold Functions for Decision Lists* (ISAAC 2022, arXiv:2207.09371), show nontrivial degree/weight representations for ordinary Boolean decision lists.

**What it has that CL-C lacks:** the rules are a fixed list of Boolean terms over a fixed input cube. Our local rules are indexed by a prefix which itself is the result of previous graph-dependent choices. Replacing each adaptive query by a polynomial-threshold predicate and then composing a generic PTF representation risks degree multiplication. Moreover, the source requires real vector outputs with a `1` versus `1/2` margin, not merely the sign of one final Boolean polynomial.

So this theorem validates the idea that “first satisfied rule” can sometimes be algebraically compressed, but it does not provide the required adaptive search-vector compiler.

## 7.3 Lovett--Wu--Zhang 2020: mild random restrictions compress decision lists

Shachar Lovett, Kewen Wu and Jiapeng Zhang, *Decision List Compression by Mild Random Restrictions* (STOC 2020), prove that small-width decision lists simplify under random restrictions and can be approximated by smaller lists.

**What it has that CL-C lacks:** again, a fixed small-width decision list whose rule vocabulary exists before the restriction. In CL-C, the problematic vocabulary is the exponentially branching family of graph-dependent prefixes. A random restriction would have to suppress almost all off-path prefixes while preserving one coherent clique path and while remaining convertible to a deterministic degree-`O(log n)` vector polynomial. No theorem located in this bounded search gives that transfer.

## 7.4 Current-literature failure summary

The useful neighboring literature can compress **local algorithms** or **fixed decision lists**. The unresolved object here is an **adaptive witness tree of low-degree threshold queries with coherent vector output**. That is a sharper description of what must be invented or circumvented.
