## 4. B9 RANDOMIZE — exact sample-size-stable random boundary counts

The previous guard-padding theorem showed that a deterministic low-weight guard prefix neutralizes every query delay `h(n)` with `limsup h(n)/n < alpha_imm`, but an unrestricted algorithm can simply wait past a deterministic boundary. The natural next attempt is to randomize the guard/core boundary.

There is a clean way to do this that is exactly compatible with the source's **fixed-size** uniform sampling, not merely iid sampling.

Fix total size `n` and exact sample size `s`; write

`r := n-s`

for the number of unsampled elements. Let `J in {0,...,n}` be a latent guard-prefix length. Conditional on `J=j`, the first `j` preliminary positions are designated guards, so after the uniform exact-size sample the number `U` of unsampled guards satisfies

\[
\Pr(U=u\mid J=j)
=
\frac{\binom{j}{u}\binom{n-j}{r-u}}{\binom nr}.
\tag{4.1}
\]

Now choose a probability measure `nu` on `[0,1]` and the length prior

\[
\boxed{
\Pr(J=j)
=
\binom nj\int_0^1\theta^j(1-\theta)^{n-j}\,\nu(d\theta).
}
\tag{4.2}
\]

This is simply a binomial-mixture law on the *number* of guards. The actual guards may still be put in a deterministic prefix once `J` is drawn; only the count law matters for the following thinning identity.

### Proposition 4.1 — exact hypergeometric thinning consistency

Under (4.1)-(4.2), for every exact sample size `s`,

\[
\boxed{
\Pr(U=u)
=
\binom ru\int_0^1\theta^u(1-\theta)^{r-u}\,\nu(d\theta),
\qquad 0\le u\le r.
}
\tag{4.3}
\]

Thus exact fixed-size deletion maps the `n`-point binomial-mixture boundary prior to the **same mixing law `nu`** on the remaining `r=n-s` points.

### Proof

For a fixed `theta`, imagine `n` abstract guard indicators that are iid Bernoulli(`theta`). Their total count `J` is Binomial(`n,theta`). Choose the `r` unsampled coordinates uniformly without replacement, independently of those indicators. Conditional on which coordinates were chosen, their guard indicators are still iid Bernoulli(`theta`), so their total `U` is Binomial(`r,theta`).

Conditional only on the total count `J=j`, the number of ones among a uniform `r`-subset has exactly the hypergeometric law (4.1). Therefore mixing (4.1) against the Binomial(`n,theta`) law gives Binomial(`r,theta`). Finally integrate over `theta~nu`. This proves (4.3). QED.

The argument is exact finite-`n` arithmetic and uses the source fixed-size sample directly; no iid approximation is involved.

### Beta-binomial specialization and a scale-free exact hazard

Taking `nu = Beta(a,b)` gives

\[
J\sim\operatorname{BetaBinomial}(n;a,b)
\quad\Longrightarrow\quad
U\sim\operatorname{BetaBinomial}(r;a,b)
\tag{4.4}
\]

for every exact sample size.

The especially simple choice `a=b=1` makes both `J` and `U` uniform on their count ranges:

\[
\Pr(J=j)=\frac1{n+1},
\qquad
\Pr(U=u)=\frac1{r+1}.
\tag{4.5}
\]

If ordinary observations have certified that exactly `t` guards have survived and the boundary has not yet been crossed, then in this count-only model the posterior hazard that the guard block ends there is

\[
\boxed{
\Pr(U=t\mid U\ge t)=\frac1{r-t+1}.
}
\tag{4.6}
\]

This is the scale-free finite-population analogue of the desired randomized boundary: it works simultaneously for **every exact sample size** because the entire family is closed under hypergeometric thinning.

Outcome B9: **structurally successful but not a source endpoint theorem**. Random boundary counts can be made exactly sample-size-stable. The remaining difficulty is not the fixed-size thinning marginal; it is the joint ordinal/query experiment generated by the boundary and the core.

## 5. B24 FIND THE EXTREMAL OBJECT — the naive hazard shield has an exact `1/2` obstruction

The clean count hazard (4.6) is not enough. The simplest ordinal implementation of a hidden boundary fails for a much more basic reason.

Consider **any** distribution on `J>=0` and the following preliminary-order architecture at sample size `s=0`:

1. conditional on `J=j`, there are `j` guards first;
2. the guards have strictly decreasing weights

\[
w(g_1)>w(g_2)>\cdots>w(g_j);
\]

3. every guard is below every core element;
4. the **first core element is the global maximum**.

No assumption is made on the law of `J`; it may be geometric, beta-binomial, scale-free, or arbitrary.

Let

`q := P(J=0)`.

Two deterministic **no-query** ordinal policies already defeat every such hazard law.

Policy `P0`: select the first arrival. It wins whenever `J=0`, so

\[
\Pr(P_0\text{ wins})=q.
\tag{5.1}
\]

Policy `P1`: reject the first arrival and then select the next record. If `J>=1`, the first arrival is `g_1`, which is a record; every later guard is lighter than `g_1`, hence is not a record; and the first core element is the global maximum, hence is exactly the next record. Therefore

\[
\Pr(P_1\text{ wins})=1-q.
\tag{5.2}
\]

Consequently the value of this entire random-boundary architecture at the legal fixed sample size `s=0` obeys

\[
\boxed{
\sup_A\Pr(A\text{ wins})
\ge
\max\{q,1-q\}
\ge \frac12.
}
\tag{5.3}
\]

The extremal boundary prior for these two policies merely equalizes them at `q=1/2`; it still leaves value at least `1/2`, far above the current unrestricted upper endpoint `0.37321` and above the conjectured `1/e`.

### Interpretation

This is an exact obstruction to the most obvious B9/B24 plan. Randomizing **only the location** of a decreasing low-weight guard/core boundary does not hide the boundary in the ordinal record process. When the core begins with the maximum, the boundary is encoded by the transition from the first guard record to the next record. No choice of count hazard can repair that.

Therefore a useful randomized shield must also provide **ordinal camouflage**: pre-core observations must have record/query statistics that resemble those inside the hard core, so crossing the boundary is not equivalent to seeing the next record. In particular a successful construction needs more than a memoryless or scale-free law for `J`.

Outcome B24: **negative but decisive for the naive architecture**. The exact count-hazard equalizer exists, but a decreasing-guard/max-first-core implementation has minimax value at least `1/2` already at `s=0`.
