## 4. Why the finite certificate is rigorous

I reuse the fixed-edge normalization proved in the previous report. For completeness, the dependence is explicit.

Let `C` be a Paley clique with two vertices `a,b`. Since `b-a` is a nonzero square, the affine map

`x -> (x-a)/(b-a)`

is a Paley automorphism carrying `a,b` to `0,1`. Hence every clique of size at least two is equivalent to `{0,1}` plus a clique in

`H_p = G_p[N(0) ∩ N(1)]`.

For prime `p ≡ 1 mod 4`, the common-neighbor graph has exactly `(p-5)/4` vertices; the checker independently verifies the realized size `Hn=(p-5)/4` on each row.

The branch-and-bound search in `H_p` is exact. At each recursive node it greedily colors the current candidate subgraph. If the coloring uses `c` colors, no clique in that candidate set has size greater than `c`; pruning when the current partial clique plus this bound cannot beat the incumbent is therefore sound. The separate decision pass asks specifically whether `H_p` has a clique large enough to make a clique of size `omega(G_p)+1` in `G_p`. Every new run terminates with `found=false`; the archived row records the complete deterministic traversal counts and digest. Together with an explicit clique witness of size `omega(G_p)`, this gives equality.

The transcript-audit script is intentionally weaker than rerunning the search: it checks coverage and witnesses, while the exact nonexistence conclusion comes from the executed deterministic decision solver itself. This distinction is preserved rather than treating a hash as a standalone proof object.
