# 6. Move 15 — BREAK THE SYMMETRY ON PURPOSE: test whether Lueker's canonical order is leaving structural slack

The more important long-range idea this run was **not** another z digit. I asked whether the finite machine could be improved by changing the canonical representative among optimal LCS matchings.

Lueker's canonical key orders matched pairs from the end using the ordered coordinate pair `(i,j)` and his backtracking resolves ties by a fixed top/left/diagonal priority. A first obvious symmetry-breaking test is to reverse the top/bottom orientation. That produces only the globally transposed construction, which is isomorphic under exchanging the two iid strings; it cannot improve the spectral bound by itself.

I then considered a genuinely symmetric/balanced key, schematically replacing each ordered pair `(i,j)` by
\[
(\max\{i,j\},\min\{i,j\})
\]
inside the reverse lexicographic canonicity key. The attraction is that such a rule could prefer geometrically balanced endpoints and might yield a smaller accepting automaton or a stronger transfer operator than the fixed top-first convention.

I did **not** promote this to a theorem. The existing Lueker proof needs much more than uniqueness of a globally chosen optimal matching: it needs the decomposition of the canonical matching into minimal match pairs and, critically, the padding/noncanonicity locality property that makes history-h acceptance valid. Those facts are proved for Lueker's specific order. A balanced global order is not automatically generated by a local greedy backtracking rule, and I do not yet have an exchange lemma proving the required locality.

**Outcome of move 15: the simple transposed order is exactly isomorphic and gives no gain; the genuinely balanced order remains a live structural idea, but is not source-valid until its minimal-pair decomposition and padding-locality lemmas are proved.**

# 7. Move 20 — FIND WHY THE ALGORITHM FAILS: the missing lemma for a better canonical automaton

The precise obstruction to replacing Lueker's order is now identified.

A candidate canonical order `K` is useful for an h-history machine only if one can prove the implication behind Lueker's finite-memory construction:

\[
\boxed{
\text{if a partial minimal-pair list is noncanonical, then every sufficiently padded extension remains noncanonical.}
}
\tag{7.1}
\]

Together with a minimal-pair decomposition, (7.1) lets the machine discard histories forever using only its finite boundary data. Merely defining a more symmetric total order on full optimal matchings does not establish (7.1). A naive local rule such as “when both deletion directions preserve LCS length, decrement the larger coordinate” can disagree with the globally optimal balanced reverse key, because an early locally balanced move can alter the entire later sequence of pair keys.

Therefore the exact thing a new canonical construction must contain, and the current balanced idea lacks, is an **exchange/local-consistency theorem** connecting its global key to local boundary DP choices. Without that theorem, using the balanced machine could accidentally exclude true canonical decompositions and would invalidate an upper bound.
