## 4. Orbit reduction for H32

Multiplication by `H32` on `Z_514` has the exact orbit profile

\[
16\text{ orbits of size }32,\qquad\{0\},\qquad\{257\}.
\tag{4.1}
\]

Let the sixteen large orbits be `O_1,...,O_16`.

An H32-invariant subset of size 256 must be a union of exactly eight large orbits and neither fixed point. Indeed, if it uses `a` large orbits and `f` fixed points, then

\[
32a+f=256,\qquad f\in\{0,1,2\},
\]

forcing `(a,f)=(8,0)`. Hence the exact number of candidates for `X_1` is

\[
\binom{16}{8}=12870.
\tag{4.2}
\]

Likewise, an H32-invariant subset of size 257 must contain exactly eight large orbits and exactly one fixed point, giving

\[
2\binom{16}{8}=25740
\tag{4.3}
\]

candidates for each of `X_2,X_3,X_4`.

For an H32-invariant set `X` and `h in H32`, multiplication by `h` gives a bijection between the ordered pairs counted by `nu_X(t)` and those counted by `nu_X(ht)`. Therefore

\[
\nu_X(ht)=\nu_X(t).
\tag{4.4}
\]

The nonzero shifts themselves split into sixteen H32-orbits of size 32 and the singleton `{257}`. Consequently every candidate is represented exactly by a 17-component integer signature

\[
s(X)=(\nu_X(t_1),\ldots,\nu_X(t_{17})),
\tag{4.5}
\]

one representative per nonzero shift orbit, and (3.1) is equivalent inside the H32-invariant class to

\[
s(X_1)+s(X_2)+s(X_3)+s(X_4)
=(512,\ldots,512)\in\mathbb Z^{17}.
\tag{4.6}
\]

The checker verifies the shift-orbit constancy directly on deterministic sample candidates across **every** element of every shift orbit, in addition to deriving signatures by exact bitset population counts.

## 5. Exact exhaustive certificate

All 12,870 size-256 candidates and all 25,740 size-257 candidates were enumerated exactly. After deduplicating **identical exact 17-vectors only**, there are

\[

Deduplication cannot remove an existence witness because equation (4.6) depends only on the signature vectors and repetitions remain allowed among the three size-257 blocks.

To make the four-way exact search feasible, define the fixed additive map

\[
\psi:\mathbb Z^{17}\longrightarrow\mathbb Z/2^{64}\mathbb Z,
\qquad
\psi(v)=\sum_{j=0}^{16}c_jv_j\pmod{2^{64}},
\tag{5.1}
\]

where the deterministic coefficients in the checker are

\[
c_j=\mathtt{0x9E3779B185EBCA87}
\mathbin{\mathrm{xor}}
\left(j\cdot\mathtt{0xD1B54A32D192ED03}\bmod2^{64}\right).
\tag{5.2}
\]

Let `A` denote the exact set of 6470 size-256 signatures, `B` the exact set of 6563 size-257 signatures, and `T=(512,...,512)`.

If (4.6) had a solution, then after grouping two of the three size-257 signatures we would necessarily have

\[
\psi(b_2)+\psi(b_3)
=
\psi(T)-\psi(a)-\psi(b_1)
\quad\text{in }\mathbb Z/2^{64}\mathbb Z.
\tag{5.3}
\]

The checker constructs **all** unordered-with-repetition `B+B` hash values,

\[
\binom{6563+1}{2}=21,539,766,

and all ordered `T-A-B` hash values,

\[
6470\cdot6563=42,462,610.
\]

After exact unsigned-64-bit sorting and a deterministic two-pointer merge, the two sets have **empty intersection**.

This emptiness is an exact one-sided nonexistence certificate. No injectivity or probabilistic collision assumption is used: if two exact 17-vectors were equal, additivity of `psi` would force equal residues. Hash collisions can create a *false positive* intersection, but they cannot erase a true equality. Therefore an empty hashed intersection proves that (4.6) has no exact vector solution.

Hence:

\[
\boxed{\text{There is no H32-invariant cyclic BGS family }
(514;256,257,257,257;512).}
\tag{5.4}
\]

Because every H64-invariant block is H32-invariant, (5.4) strictly subsumes the earlier H64 restricted exclusion.
