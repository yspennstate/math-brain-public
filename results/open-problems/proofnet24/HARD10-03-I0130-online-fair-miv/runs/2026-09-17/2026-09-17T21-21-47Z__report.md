## 3. Setup: exact PROP1 safety for two agents

It suffices to construct, for every deterministic algorithm, an adaptive instance for two agents with exact MIVs `p_1=p_2=1`.

For a prefix/final instance and agent `i`, write

- `B_i` for the value of the bundle allocated to `i`;
- `R_i=max{v_i(g): g notin A_i}`, with `R_i=0` if no good lies outside `A_i`;
- `V_i` for the value of all goods to `i`.

Define the two-agent PROP1 safety

` s_i := 2(B_i+R_i)-V_i. `

The achieved PROP1 factor for agent `i` is exactly

` 2(B_i+R_i)/V_i = 1+s_i/V_i `

whenever `V_i>0`.

After each agent has missed a unit-valued good, `R_i=1` forever provided every later item value is at most one.  From that point on, an item of value `x<=1` changes that agent's safety by exactly

- `+x` if the agent receives it;
- `-x` if the agent misses it.

This linear safety calculus is the mechanism behind Du--Sun's adversary and the optimization below.

### Proof

Set

`N=127`,

`r=4/129`,

`gamma=1/16-r=65/2064`.

The adversary has the same three-phase architecture as Du--Sun, but the block count and terminal slack are optimized.

### Phase 1: force the stable unit correction

Present three goods valued `1` by both agents.

If one agent receives all three, the other has `B=0`, `R=1`, `V=3`, hence safety `-1`.  Stopping immediately already gives PROP1 factor `2/3`, which is below `U_new`.

Otherwise the allocation is a `2-1` split.  Call the two agents `H` and `L` according to their current safeties.  Directly,

`(h,l)=(3,1)`.

Both agents have now missed a unit good, so from here onward `R_H=R_L=1` permanently as long as later values are at most one.

### Phase 2: forcing blocks

At the start of every completed block we maintain labels satisfying

`h<=3`, `l<=1`.

If `l<=r`, go directly to Phase 3.

Otherwise `l>r`, so `l-r` is nonnegative.  Present a first good with values

`v_H=1`, `v_L=l-r`.

If the algorithm allocates this good to `H`, then the safety update is

`h' = h+1 <=4`,

`l' = l-(l-r)=r`.

Go immediately to Phase 3, with one agent of safety at most `r` and the other at most `4`.

Suppose instead the first good is allocated to `L`.  The new safeties are

`(h-1, 2l-r)`.

Now present a second good valued `1` by both agents.

If it is allocated to `H`, the state becomes

`(h, 2l-r-1)`.

Since `h<=3` and `l<=1`, this again has one coordinate at most `3` and the other at most `1`.

If the second good is allocated to `L`, the state becomes

`(h-2, 2l-r+1)`.

Here `h-2<=1`, while `2l-r+1<=3-r<3`; swapping the labels restores the invariant `h<=3`, `l<=1`.

In either completed-block branch, the total safety changes from `h+l` to

`h+2l-r-1`,

so the change is

`l-r-1 <= -r`

because `l<=1`.  Therefore every completed block decreases the sum of the two safeties by at least `r`.

If 127 full blocks complete without an earlier transition to Phase 3, their total safety is at most

`4-127r = 4-508/129 = 8/129 = 2r`.

For two real numbers whose sum is at most `2r`, at least one is at most `r`.  Relabel that agent `L` and the other `H`.  The completed-block invariant gives `H<=3`, so in every possible transition to Phase 3 we have the uniform bounds

`l<=r`, `h<=4`.

This is the first place where the source constant leaves slack: it is enough to force the **minimum** safety below `r`, so total safety `<=2r` suffices.  One need not drive the total all the way below `r`.

### Phase 3: five-item exact trap

Present five goods.  Every one has value `1` to `H`.  Their values to `L` are

`a_1=1/16`,
`a_2=1/8`,
`a_3=1/4`,
`a_4=1/2`,
`a_5=1`.

Equivalently,

`a_j = 2^(j-1)(r+gamma)`

because `r+gamma=1/16`.

Assume first that `L` receives each of the preceding trap goods.  Before trap item `j`, its safety is at most

`r + sum_{k<j} a_k
 = r + (2^(j-1)-1)(r+gamma)
 = 2^(j-1)r + (2^(j-1)-1)gamma`.

If `L` misses item `j`, its safety is therefore at most

`2^(j-1)r + (2^(j-1)-1)gamma
 - 2^(j-1)(r+gamma)
 = -gamma`.

Hence, unless the adversary can already stop with an agent of safety at most `-gamma`, the algorithm must allocate the first four trap goods to `L`.

Those four goods all have value `1` to `H`.  Thus `H`, which entered Phase 3 with safety at most `4`, misses four unit-valued goods and reaches safety at most `0`.

On the fifth trap good there are only two cases:

1. If it is allocated to `H`, then `L` misses it and has safety at most `-gamma` by the calculation above.
2. If it is allocated to `L`, then `H` misses another unit-valued good and has safety at most `-1 <= -gamma`.

So every deterministic allocation path ends with some agent satisfying

`s_i<=-gamma`.

`p_1=p_2=1`

goods.  Hence for the failed agent `V_i<=262`.  From `s_i<=-gamma`,

`2(B_i+R_i)/V_i = 1+s_i/V_i

we obtain

## 6. B20 — FIND WHY THE ALGORITHM FAILS: the source reciprocal potential has a sharp 1/2 barrier

Write the source reciprocal-potential parameter as `beta`; for target `alpha` the naive scaling would be `beta=alpha/n`.  In an ordinary update the source algebra uses

`q^- = q-beta*y`,

`q^+ = q+(1-beta)y`,

`F = 1/q^- - 1/q`,

`G = 1/q^- - 1/q^+`.

Direct algebra gives

`F/G = beta + beta(1-beta)y/q`.

Initially all agents have `q=1-beta`.  Give every agent the same normalized value `0<y<1`.  Then all `F,G` are equal and, regardless of which tied agent receives the good, the reciprocal potential changes by

`Delta Psi = nF-G`.

At the initial state,

`F/G = beta(1+y)`,

so

`Delta Psi/G = n beta(1+y)-1 = alpha(1+y)-1`.

For every `alpha>1/2`, choose

`1/alpha-1 < y < 1`.

Then `Delta Psi>0` on the very first round, independently of tie-breaking.  Therefore the **unchanged Du--Sun reciprocal potential and allocation rule cannot be extended past `1/2` merely by increasing beta**.
